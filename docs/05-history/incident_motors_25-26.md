# Incident: มอเตอร์ 25/26 หลุด

> ย้ายมาจาก vault ของผู้ดูแล (`02 Real Robot/Incident Motors 25-26.md`) เมื่อ 10/11/2026

## อาการ
slot **25 (right_elbow)** และ **26 (right_wrist_roll)** พร้อมกัน:
`vol 0`, `temperature [0, 0]`, `motorstate 0x80000000`, q ค้างที่ 0 · ไหล่ขวา (22–24) ปกติ 52.5 V
ข้อมือต่ออยู่หลังศอก → น่าจะเป็นจุดเดียวกัน (ศอกหรือสาย/ขั้วต่อช่วงไหล่ → ศอก)

## ข้อมูลดิบที่ควรส่ง Unitree
| ช่อง | มอเตอร์ปกติ | 25 / 26 ตอนเสีย |
|---|---|---|
| `motorstate` | 0 | `0x80000000` / `0x40008000` / `0x8000` (เปลี่ยนไปมา 25 กับ 26 เป็นรหัสเดียวกันเสมอ) |
| `reserve` | `[0, 1142 หรือ 1143, 4, 0]` | `[602102, 1143, 4, 0]` / `[602101, 1143, 4, 0]` |
| `mode` | 1 | 0 (ทั้งแขนขวา 22–26) |

- ภายในการวัดหนึ่งครั้ง (3–10 s) รหัส **นิ่ง** ไม่กระพริบ · ไหล่ขวาไม่หลุดเลยสักข้อความ
- ไม่มีตาราง error code ของ motorstate G1 ที่ Unitree ประกาศ → ต้องให้ Unitree แปล

## วิเคราะห์
- รอบ 2/11 ไม่ได้กด L2 + A → ปุ่มไม่ใช่สาเหตุหลัก
- สมมติฐานที่เข้ากับทุกอย่าง: **ศอกขวาถูกดันเกินระยะ** (ตอนเหยียดตัว/ตอนล้ม) → มอเตอร์เข้าโหมดป้องกันแบบค้าง (latched) → ถอดแบตไม่หายถ้ายังค้างนอกระยะ → หมุนกลับ + reset จึงหาย
- ยังยืนยันไม่ได้: บิต `0x80000000` ไม่มีในตาราง error ที่หาได้
- 3/11 สองสมมติฐานที่เหลือ:
  - **A. ท่าแขนตอนบูต** มอเตอร์อ่านตำแหน่งเริ่มต้นแล้วไม่ยอมเริ่มถ้าอยู่ในช่วงที่อ่านไม่ได้ → บิดแขนก่อนเปิดจึงหาย (ตรงกับที่พี่ทำ 2/11)
  - **B. สาย/ขั้วต่อหลวม** บิดแขนแล้วหน้าสัมผัสกลับมาแตะ
  - หลักฐานเอียงไปทาง A: หลังหายแล้วหมุนศอก/ข้อมือจนสุดทั้งสองทาง 136 s ไม่หลุดเลย · แต่เป็นการทดลองครั้งเดียว
- ไม่มีคำสั่ง SDK สำหรับ "เคลียร์ error มอเตอร์" หรือรีเซ็ตบัส: บัสมอเตอร์ต่อกับบอร์ด 161 ซึ่งปิดไว้ ถอดแบตคือการรีเซ็ตที่หนักที่สุดที่ทำได้
- ไม่ใช่โปรแกรมของเรา: เราไม่เคยติดตั้งอะไรลงหุ่น (SSH เข้า 164 ครั้งแรก 3/11) และ 2/11, 3/11 หลุดตั้งแต่บูตก่อนส่งคำสั่งใดๆ

## ทำเมื่อเจออีก
1. `robot_health.py` ยืนยัน (FAIL offline)
2. ดูแขนขวา: รอยกระแทก, สาย
3. ปิดเครื่อง → **บิดแขนขวาไปจนสุด** → เปิดตอนแขวน ไม่กดปุ่ม → อ่านซ้ำ (3/11 ได้ผล)
4. ถอดแบต 2 นาที (30/10 ได้ผล, 2/11 และ 3/11 ไม่ได้ผล)
5. ถ้าไม่หาย: แอป Unitree Explore (ดูวิดีโอ calibrate 23 DoF / network setting ในแอป) หรือ Unitree support
6. หลังแก้: **[Offset Check](../02-how-to/offset_check.md) ก่อนรัน policy เสมอ**

## ทดลองต่อ (ยืนยันสมมติฐาน A)
บูต 2 รอบตอนแขวน: (1) แขนห้อยปกติ (2) บิดแขนแบบเดิม · ถ้า (1) เสีย (2) หาย ซ้ำสองครั้ง → ใส่เป็นขั้นตอนก่อนเปิดเครื่องใน [Test Day Procedure](../02-how-to/test_day_procedure.md) · จดท่าแขนตอนปิดเครื่องทุกครั้ง

## ป้องกัน
ไม่กด L2 + A · ปิดเครื่องตอนแขวน · ดูศอกขวาใน monitor ว่าเข้าใกล้ limit ไหม
