# Day 4: ซ้อมวันทดสอบหุ่นใน sim

**เป้าหมาย:** ซ้อมทุกขั้นของวันทดสอบหุ่นจริงด้วยเครื่องมือชุดเดียวกัน แต่ชี้ไปที่ sim และฝึกการหยุดจนทำได้โดยไม่ต้องคิด
**ก่อนเริ่ม:** Day 1–3 ผ่านแล้ว · อ่าน [basics/05](../04-explanation/basics/05_dds_domain_interface.md) อีกรอบ

> วันทดสอบจริงทุกอย่างเกิดขึ้นเร็ว และหุ่นหนักราว 32 kg การซ้อมใน sim ให้คล่องคือส่วนหนึ่งของความปลอดภัย **ไม่ซ้อม = ไม่ได้เข้าวันทดสอบ**

---

## FSM ของ g1_ctrl (ต้องจำได้)
```
Passive  ──(L2 + ↑)──▶  FixStand  ──(R2 + A)──▶  Velocity (policy)
   ▲                        │                          │
   └────────(L2 + B)────────┴──────────(L2 + B)────────┘
```
| โหมด | ทำอะไร | คีย์ใน sim |
|---|---|---|
| Passive | kp = 0 หนืดอย่างเดียว ไม่ดึงไปท่าไหน | `p` |
| FixStand | ค่อยๆ ไปท่ายืนใน 3 วินาทีแล้วค้าง (gain ของ Unitree) **ไม่มีการทรงตัว** | `u` |
| Velocity | policy ควบคุม | `v` |

บนหุ่นจริง**คีย์บอร์ดใช้ไม่ได้** (เปิดเฉพาะบน `lo`) ต้องใช้รีโมทเท่านั้น

## กลไกหยุด (ต้องจำได้)
| กลไก | ทำงานเมื่อ | หมายเหตุ |
|---|---|---|
| **L2 + B → Passive** | กดเมื่อไรก็ได้ ทุกโหมด | ทางหลัก Passive = kp 0 หุ่นจะทรุด **ให้เชือกรับน้ำหนักก่อนกด** |
| LowState timeout → Passive | ไม่ได้รับ `rt/lowstate` 100 ms | ถ้าเครือข่ายขาด คำสั่ง Passive ก็อาจไปไม่ถึงหุ่น |
| bad_orientation → Passive | ใน Velocity เอียงเกิน 49° | ช้าเกินจะกันล้ม คนต้องกดก่อนที่ ~15° |

**หยุดทันทีเมื่อ:** joint หมุนผิดทิศ, สั่นถี่หรือมีเสียงแปลก, monitor ขึ้น `MISMATCH` / `STALE` / `OUT`, อุณหภูมิเกิน 70 °C, เอียงเกิน ~15°, หรือมีใครพูดว่า "หยุด"

## 1. เปิด sim
**คำสั่งเต็ม:**
```bash
cd repos/unitree_rl_mjlab/simulate/build
env -u CYCLONEDDS_URI LD_LIBRARY_PATH=/opt/unitree_robotics/lib ./unitree_mujoco -i 1
```
**ทางลัด:** `make sim`

ใน MuJoCo: **Pause** แล้ว **Load key 0**

## 2. เปิดชุดเครื่องมือวันทดสอบ (ชี้ไปที่ sim)
อีก terminal หนึ่ง
**คำสั่งเต็ม:**
```bash
conda activate g1_sdk && cd repos/unitree_rl_mjlab && unset CYCLONEDDS_URI
IFACE=lo bash deploy/robots/g1_23dof/scripts/deploy_byobu.sh 1 run
```
**ทางลัด:** `make deploy-sim`

**ผลที่ต้องเห็น:** แถบสีเขียว `[SIM] deploy panes · lo · domain 1` แล้ว byobu เปิด 4 ช่อง
```
+-----------------------+-----------------------+
| T1 lowstate_monitor   | T2 lowcmd_monitor     |   อ่านอย่างเดียว บันทึก CSV
+-----------------------+-----------------------+
| T3 g1_ctrl            | T4 checks / pd_check  |   T3 = ตัวเดียวที่ส่งคำสั่งมอเตอร์
+-----------------------+-----------------------+
```
ทุกช่อง**พิมพ์คำสั่งไว้ให้แต่ยังไม่รัน** ตั้งใจให้คนตรวจก่อนแล้วกด Enter เอง
ย้ายช่อง: คลิกเมาส์ หรือ Shift + ลูกศร (ปุ่มของ byobu: [basics/08](../04-explanation/basics/08_tmux_and_byobu.md) · **อย่ากด Ctrl+F6** = ปิด pane ทันที)

## 3. ซ้อมตามลำดับวันจริง
| # | ทำ | ผลที่ต้องเห็น |
|---|---|---|
| 1 | T4: กด ↑ หา `gain_check ...v0` แล้ว Enter | `PASS` |
| 2 | T1 Enter, T2 Enter | ตัวเลข lowstate / lowcmd ขยับ บรรทัด DDS เป็น `SIM` |
| 3 | T3 Enter | `DDS: domain 1 on lo (SIM, keyboard on)` → `Connected` → โหลด policy `v0` |
| 4 | T3: `u` (FixStand) แล้ว MuJoCo **Run** | หุ่นค่อยๆ ไปท่ายืน T2 ขึ้น gain ของ FixStand |
| 5 | **ซ้อมหยุด:** T3 กด `p` | กลับ Passive ทันที หุ่นใน sim ทรุด |
| 6 | Load key 0 ใหม่ → `u` → `v` (Velocity) → `w` เดิน | T2 ขึ้น `gains match: Velocity` |
| 7 | **ซ้อมหยุดระหว่างเดิน:** `p` | หยุดทันที |
| 8 | T1, T2: Ctrl-C (ปิด CSV) | ได้ไฟล์ `~/g1_state_<วันที่>_run1.csv`, `~/g1_cmd_..._run1.csv` |
| 9 | T4: กด ↑ หา `pd_check ...` แล้ว Enter | รายงานผล kp/kd จาก CSV |

ทำซ้ำข้อ 5 กับ 7 จนกดได้ทันทีโดยไม่ต้องคิด บนหุ่นจริงจะเป็น **L2 + B** แทน `p`

## 4. ปิดให้ถูกลำดับ
1. T3: Ctrl-C หยุด g1_ctrl **ก่อน**
2. ออกจาก byobu: F6 (ทุกอย่างยังรันต่อ) แล้วปิด session:
```bash
tmux kill-session -t g1deploy
```
3. ปิดหน้าต่าง MuJoCo

`deploy_byobu.sh` ตั้งใจ**ไม่ปิด** session ให้เอง เพราะบนหุ่นจริง g1_ctrl ใน session อาจกำลังพยุงหุ่นอยู่
